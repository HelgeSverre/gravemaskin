# Research: House Architecture (Ironsight / Bloom archaeology)

> Produced by the gravemaskin research workflow, 2026-08-28.

## Summary

The author's house architecture, established in /Users/helge/code/fsharp-of-duty (Ironsight, mature) and /Users/helge/code/bloom (BloomCrimes, early WIP), is a strict two-project split enforced by F# compile order: a pure, deterministic, headless Core library (Prelude -> Noise -> MathEx -> Domain -> Tuning -> ProcGen/* -> gameplay modules -> Sim.fs last) with zero graphics dependencies, and a Silk.NET "Shell" executable (Settings -> Input -> GlUtil -> Shaders -> Hud -> Particles -> Audio -> Renderer -> Program.fs last) that owns all mutable OS/GL/audio state. The game loop lives in Program.fs as a classic fixed-timestep accumulator inside Silk.NET's window.add_Update: accumulator clamped to 0.25s, `while accumulator >= fixedStep` at TickRate=60 (a [<Literal>] in Tuning), each tick calling the pure `Sim.step : InputFrame -> World -> struct (World * GameEvent list)`; add_Render interpolates `previous`/`current` worlds by alpha = accumulator/fixedStep and feeds transient GameEvents to the imperative Renderer/AudioSystem classes. Everything gameplay-numeric lives in Tuning.fs as named constants with rationale comments; Domain.fs is types only; determinism comes from a struct RNG threaded through World (splitmix64 in Ironsight, xorshift32 mutable struct in bloom) plus <Deterministic>true</Deterministic>, TreatWarningsAsErrors, LangVersion preview, net10.0 everywhere.

Critically for gravemaskin, bloom shows the author already relaxes purity when perf demands it: bloom's `World` is a mutable class with pooled fixed-size arrays (maxBullets=4096 etc., cursor indices, `let mutable` fields) advanced by an `Update dt` member — the "functional core" boundary is the *module seam and headlessness*, not immutability. That is exactly the shape a BEPUphysics v2 + voxel-soil sim needs: keep Domain (types), Tuning (constants), and pure helpers (SDF math, soil material curves) in Core, but let the Sim own a mutable BEPU Simulation and chunked soil arrays behind a `step` function that still takes an InputFrame and returns events. Tests are headless xUnit + FsCheck driving Sim.step for hundreds of ticks via a TestKit module of world-builders and step-loops; tooling is a justfile with a self-installing SDK shim, dotnet format lint gate, `just check` = lint+build+test, and CI/release workflows that publish self-contained single-file builds per RID with a universal macOS .app (launcher.sh picking x64/arm64), ad-hoc codesigned, pkgbuild installer.

## Key findings

- Project split: src/{Name}.Core (pure sim, procedural assets, no Silk.NET reference) + src/{Name} (Silk.NET client exe, namespace {Name}.Shell) + tests/{Name}.Tests; Ironsight adds src/Ironsight.Server (ASP.NET WebSocket) — README states 'F# compile order enforces the dependency direction'.
- Core compile order (Ironsight.Core.fsproj): Prelude.fs, Noise.fs, MathEx.fs, Domain.fs, Anatomy.fs, Tuning.fs, ProcGen/* (Materials, MeshGen, Guns, AudioSynth, FontGen, Humanoid), Maps/*, then gameplay modules (Movement, Weapons, Ballistics, ...), Sim.fs LAST. Client order: Settings, MapStore, UiLayout, Menu, SettingsUi, Input, GlUtil, Shaders, NetworkClient, Hud, Particles, Audio, Ragdoll, Renderer, Program.fs last.
- Game loop (src/Ironsight/Program.fs:473-482, 823-859): window.add_Update does `accumulator <- min 0.25 (accumulator + elapsed); while accumulator >= fixedStep do ... Sim.step ...; accumulator <- accumulator - fixedStep` with fixedStep = 1.0/60.0 from `Tuning.TickRate = 60` ([<Literal>]). Two immutable world snapshots `previous`/`current`; add_Render computes alpha = accumulator/fixedStep and renders `RenderInterpolation.world alpha previous current`. Pinned alpha=1.0 when a menu freezes the offline world to avoid backdrop jiggle.
- Step function signature: `Sim.step (input: InputFrame) (world: World) : struct (World * GameEvent list)`. World is one immutable record (Tick: int64, Rng: Rng.State, Player, Soldiers array, projectiles, Level, Script, Round...). GameEvent is a large DU consumed by Renderer.HandleEvents, AudioSystem.Handle, and HUD feedback — presentation is event-driven, sim never touches GL/AL.
- Domain.fs = types only (records/DUs/[<Struct>] where hot, units of measure float32<s>/float32<hp> from Prelude); Tuning.fs = every gameplay constant + small pure curve functions, heavily commented with design rationale; Sim.fs = createWorld/createXxxWorld constructors + step pipeline (locomotion -> weapons -> projectiles -> grenades -> elemental -> AI -> objectives -> script -> round).
- Input pattern (src/Ironsight/Input.fs): InputSampler class over Silk.NET IInputContext; sim consumes only `[<Struct>] InputFrame { Sequence: int64; Move: Vector2; Look: Vector2; Buttons: InputButtons [<Flags>] enum }`. Sampler owns edge-latching, toggle-vs-hold settings, gamepad deadzone/trigger normalization (GLFW triggers rest at -1), menu-mode input suppression (snapshot held buttons on menu open so they stay dead until re-edged), and scroll-detent accumulation. Constants like StickDeadzone=0.15 live as static lets at the top of the class.
- bloom's Core deliberately breaks immutability for perf: `type World(seed)` is a class with pooled arrays (maxBullets=4096, maxEnemies=512, maxParticles=8192), cursor allocation, dozens of `let mutable` fields, and a GpuStats record with mutable fields — proving the house style is 'headless deterministic Core + thin shell', NOT 'everything immutable'. bloom also sets ServerGarbageCollection=false / ConcurrentGarbageCollection=false in Directory.Build.props for latency.
- Build config: global.json pins SDK 10.0.100 rollForward latestMajor; Directory.Build.props sets net10.0, LangVersion preview, TreatWarningsAsErrors, Deterministic. Client fsproj: PublishSingleFile=true with a load-bearing comment that Silk.NET natives (GLFW/OpenAL) must stay loose beside the exe (single-file self-extract dir is invisible to Silk's loader) and no trimming (F#+Silk reflection is trim-hostile). OpenGL context requested as Core/ForwardCompatible 4.1 (the macOS ceiling) at Program.fs:246.
- justfile conventions: variables at top (client/tests/solution paths), private `_sdk` recipe that curl-installs the SDK into .dotnet/ if global.json is unsatisfied, `dotnet := PATH="$PWD/.dotnet:$PATH" dotnet` shim, [group('run'/'build'/'test'/'format'/'tools')] annotations, `check: lint build test smoke` as pre-commit gate, [macos] `install` recipe that publishes self-contained and assembles /Applications/{Name}.app with sed-templated Info.plist + ad-hoc codesign, plus fsi-script tool recipes (tools/*.fsx) for previews/exports.
- Tests (tests/Ironsight.Tests): xUnit 2.9.3 + FsCheck.Xunit 3.3.4 + coverlet; TestKit.fs first in compile order provides canonical world builders (streetArena via LevelDsl), `stepAll first last buttons world` loops folding Sim.step and collecting events, baseline entity factories meant for record-update, and slot-lookup-by-name helpers so tests don't break when arrays reorder. Integration tests are filtered by Category (`just test` excludes, `just smoke` includes). xunit.runner.json enables parallel collections; process-global env-var tests use a DisableParallelization collection.
- CI (.github/workflows/ci.yml): checkout -> setup-dotnet 10.0.x -> restore -> `dotnet format --verify-no-changes` -> build -> test with XPlat coverage upload. Release (release.yml, tag v*): per-OS jobs publishing self-contained builds; macOS publishes BOTH osx-x64 and osx-arm64, wraps them in one .app with packaging/launcher.sh arch-switcher, ad-hoc codesigns (comment: unsigned arm64 won't exec at all), and pkgbuild's an installer; Linux gets tar.gz + .deb; Windows gets zip + Inno Setup.
- Settings pattern (src/Ironsight/Settings.fs): [<CLIMutable>] record + System.Text.Json, clamp() validating hand-edited files (with the trick of storing negatively-named bools so absent-field=false defaults right), stored under APPDATA/{name} with {NAME}_HOME env override for portable installs and tests, save-on-close and save-on-change.
- Procedural assets all live in Core/ProcGen as pure generators returning data (MeshGen -> MeshVertex arrays, FontGen -> 5x7 bitmap atlas as byte array, AudioSynth -> PCM, Guns/Humanoid -> meshes, LevelDsl/LevelCompile -> a declarative level DSL compiled to brushes+collision mesh+nav); the shell uploads them to GL/AL. bloom/src/BloomCrimes/Font.fs is a self-contained 110-line 5x7 font atlas module (simpler than Ironsight's FontGen).
- Server tick host (src/Ironsight.Server/MatchHost.fs) exposes AdvanceTick() so tests drive the authoritative sim synchronously — the same headless-steppable design any gravemaskin sim host should keep.

## Recommendations

- Mirror the layout exactly: /Users/helge/code/gravemaskin with global.json (SDK 10.0.100, rollForward latestMajor), Directory.Build.props (net10.0, LangVersion preview, TreatWarningsAsErrors, Deterministic, and copy bloom's ServerGarbageCollection=false + ConcurrentGarbageCollection=false — a 60Hz physics game wants workstation GC), Gravemaskin.sln, src/Gravemaskin.Core/, src/Gravemaskin/ (namespace Gravemaskin.Shell), tests/Gravemaskin.Tests/, justfile, .github/workflows/{ci.yml,release.yml} copied nearly verbatim with names swapped.
- Core compile order suggestion: Prelude.fs (units of measure, struct Rng — lift bloom's xorshift32 mutable-struct Rng, it is the better fit for per-particle jitter), Noise.fs (lift verbatim), MathEx.fs (lift the Aabb/ray/closest-point parts), Domain.fs (SoilMaterial, SoilCell, ChunkId, ExcavatorState, HydraulicCylinder, InputFrame, GameEvent DU), Tuning.fs (TickRate=60 [<Literal>], soil densities/cohesion/friction tables, cylinder bore/stroke/pressure, track dims — with the same rationale-comment style), then Soil/{Volume.fs,Sdf.fs,Dig.fs,Particles.fs,Settle.fs}, Excavator/{Linkage.fs,Hydraulics.fs,Tracks.fs}, ProcGen/{Materials.fs,MeshGen.fs,ExcavatorMesh.fs,FontGen.fs? or bloom Font in shell}, Sim.fs last.
- Adopt bloom's mutable-World-class pattern for the sim, not Ironsight's immutable record: gravemaskin's World should be `type World(seed)` owning the BEPU `Simulation`, `BufferPool`, chunked soil arrays, and particle pools, advanced by `member Step(input: InputFrame) : GameEvent list` (or module `Sim.step input world` returning events). BEPU2 is inherently mutable and pool-based; wrapping it in immutable snapshots would be fighting both libraries. Keep determinism the house way: seeded struct Rng + fixed 60Hz + BEPU stepped with a constant dt.
- Render interpolation must change shape: with a mutable World you cannot keep `previous = current` record snapshots. Instead have the shell copy out a small POD `RenderState` (excavator bone transforms, camera, particle positions) each tick into a double buffer and lerp those — same alpha = accumulator/fixedStep math from Program.fs:823-833, applied to an explicit snapshot struct rather than the whole world. RenderInterpolation.fs (58 lines) shows the pattern to imitate.
- Keep the GameEvent DU + HandleEvents pattern exactly: DigStarted, SoilSpilled, HydraulicStall, TrackSlip, RockStruck, EngineLoad etc. — it is what keeps Renderer/Audio out of Core and makes headless tests assert on behavior.
- Lift verbatim or near-verbatim: src/Ironsight/GlUtil.fs (101 lines: shader compile/link, VAO/VBO/IBO with interleaved layout, fixed-pointer buffer upload, setMatrix — adjust the stride for your vertex format), bloom/src/BloomCrimes/Font.fs (110-line 5x7 HUD font, simpler than Ironsight's FontGen), Ironsight.Core/Noise.fs (value noise + fbm2, exactly what terrain seeding needs), MathEx.fs geometry helpers, Settings.fs (rename IRONSIGHT_HOME -> GRAVEMASKIN_HOME), the InputSampler skeleton from Input.fs (deadzone/trigger/latch/menu-suppression logic transfers directly to ISO/SAE dual-stick mapping — put pattern selection in GameSettings like AdsToggle), justfile with its _sdk shim, and Program.fs's window setup: WindowOptions with `GraphicsAPI(ContextAPI.OpenGL, ContextProfile.Core, ContextFlags.ForwardCompatible, APIVersion(4, 1))`, borderless-fullscreen applyDisplay, framebuffer-vs-window-size retina handling, and the add_Load/add_Update/add_Render/add_Closing lifecycle.
- Tests: copy the TestKit pattern — a `TestKit.fs` with a canonical flat-ground world builder, `stepAll`/`advance` loops over Sim.step, and FsCheck properties (mass conservation across dig->loose->settle is the gravemaskin equivalent of Ironsight's PropertyTests). Drive BEPU headlessly; no window needed. Filter slow soil-churn tests with Category=Integration like `just test`/`just smoke`.
- fsproj notes to carry over: client PublishSingleFile=true WITH the loose-natives comment (Silk.NET loader cannot see single-file self-extracted natives — this will bite BEPU-era packaging too), AllowUnsafeBlocks=true in the client (GlUtil uses fixed pointers; #nowarn "9"), no trimming. BEPUphysics2 (BepuPhysics NuGet) references go in Core — it is graphics-free so the dependency direction holds; Silk.NET.* stays client-only.
- What does NOT transfer: Ironsight.Server/NetworkClient/OnlineWorld/prediction-reconciliation (~2000 lines of multiplayer — gravemaskin is single-player, skip entirely), MapStore/ServerDirectory, the GoldSrc BSP importer, Multiplayer.fs, and the Brush/CollisionMesh triangle-grid collision system (BEPU replaces it). The Menu/SettingsUi/Hud/UiLayout stack is worth copying structurally but trimming to what a sandbox needs.

## Risks

- Immutable-World cargo-culting: copying Ironsight's `{ world with ... }` record style into a BEPU2 game would allocate catastrophically at 60Hz with thousands of soil particles and fight BEPU's BufferPool model. bloom is the precedent to cite; the boundary to preserve is headless determinism, not purity.
- Render interpolation with a mutable world: the previous/current snapshot trick from Program.fs silently breaks (both names alias one object). Must introduce an explicit copied RenderState double buffer or motion will judder at monitor rates above/below 60Hz.
- BEPU2 determinism is only per-machine/per-build (it is deterministic for the same binary and thread count only if configured carefully); if the author wants Ironsight-grade replay determinism, pin the thread dispatcher's thread count and avoid solver nondeterminism — worth a spike test early (a TestKit property: same seed + same inputs -> identical excavator pose after 10k ticks).
- macOS OpenGL 4.1 ceiling: no compute shaders, no SSBOs, GLSL 410 max. Any GPU-side soil meshing (marching cubes on compute) is off the table on the primary platform — plan CPU-side chunk remeshing with the GlUtil buffer-upload path, and budget it (dirty-chunk queue per tick) or the 60Hz sim will stall the render thread.
- Single-file publish + native libs: Silk.NET natives must stay loose beside the exe (documented in Ironsight.fsproj); BEPU2 is pure managed so it adds no natives, but any future native dep (e.g. a meshing library) hits the same trap. Keep the fsproj comment.
- TreatWarningsAsErrors + LangVersion preview on .NET 10: fine for the author's style but means SDK drift can break CI; the justfile _sdk shim and global.json pin are the mitigation — keep them.
- The accumulator clamp `min 0.25` means the sim drops time under heavy load rather than spiraling — correct for a game, but for a physics sandbox a dropped-time frame during a dig can look like soil teleporting; keep the clamp but surface a debug counter when it engages.
- bloom is one commit old and has no Program.fs/game loop yet — its loop shape cannot be copied; Ironsight's Program.fs is the only real loop reference.
- GC: even with pooled arrays, F# closures/List usage in a per-tick event path allocates; Ironsight tolerates it, but with BEPU also allocating on spikes, prefer struct events or a pooled ResizeArray<GameEvent> drained per tick if profiling shows Gen0 pressure at 60Hz.
