# Research: Rendering (Silk.NET, OpenGL 4.1 on macOS)

> Produced by the gravemaskin research workflow, 2026-08-28.

## Summary

Staying on Silk.NET OpenGL 4.1 core is the right call for Gravemaskin. macOS (through Tahoe/26) still ships a conformant GL 4.1 on Apple Silicon, emulated on Metal, deprecated but with no announced kill date. The 4.1 ceiling forbids compute shaders, SSBOs, image load/store, multi-draw-indirect, and persistent-mapped buffers — but the game's heavy work (BEPUphysics v2, voxel/SDF soil sim, marching-cubes-style meshing) is CPU-side anyway, so the GPU only needs what 4.1 has in abundance: instanced arrays (glDrawElementsInstanced + glVertexAttribDivisor), UBOs, texture arrays, FBO/MRT, transform feedback, and fence syncs. The alternatives (Silk.NET WebGPU over wgpu-native, NeoVeldrid over MoltenVK) are viable escape hatches but cost a full rewrite of the author's proven idioms for no capability the game actually needs; the correct hedge is what Ironsight already does — keep all GL behind Renderer.fs/GlUtil.fs so a future backend swap touches two files, not the sim.

The rendering plan falls out of the author's existing Ironsight architecture almost verbatim. Terrain: per-chunk VAO/VBO/IBO with whole-buffer glBufferData orphaning on remesh (exactly Ironsight's GlUtil.upload pattern, which re-specs the buffer store each call and therefore never stalls), a remesh budget of ~4-8 chunks/frame, CPU normals from SDF central differences, and — the key insight for trench readability — per-vertex ambient occlusion baked during meshing from the voxel volume itself, which is nearly free, deterministic, asset-free, and better matched to holes/trenches than screen-space SSAO. Surfaces get triplanar procedural texturing in the fragment shader (a direct evolution of Ironsight's materialColor() dispatch), with per-vertex material weights, moisture-driven wet darkening, and compaction-driven roughness. Loose soil: instanced low-poly clods (20-80 tris) with a per-frame orphaned instance buffer — 20k-50k instances is comfortable on Apple Silicon at this vertex cost — backed by the existing point-sprite Particles module for dust, with cosmetic (non-physics) particles making up the visual bulk so BEPU only simulates a few thousand real clumps. Shadows: Ironsight's single 2048 ortho shadow map with front-face culling and 3x3 PCF carries over directly; fit the ortho box around the excavator's working area and it will look better than Ironsight did, since the camera orbits one machine. Sky: the fbm/palette/ridge fullscreen-triangle shader from Shaders.fs, re-paletted to overcast industrial ochre-grey.

## Key findings

- GL 4.1 exact ceiling — MISSING: compute shaders (4.3), SSBO (4.3), image load/store + atomic counters (4.2), glMultiDrawIndirect (4.3), ARB_buffer_storage/persistent-coherent mapping (4.4), immutable texture storage glTexStorage (4.2), explicit uniform locations (4.3), base-instance draws (4.2), texture views (4.3), glClipControl (4.5), DSA (4.5), BPTC/BC6H-BC7 compressed formats (4.2, absent on Apple GL), KHR_debug/ARB_debug_output (not exposed on macOS at all).
- GL 4.1 exact ceiling — AVAILABLE: GLSL 410 core; instanced rendering (glDrawElementsInstanced 3.1 + glVertexAttribDivisor 3.3); UBOs (3.1, std140, >=16KB guaranteed, 64KB typical on Apple); 2D texture arrays (3.0); transform feedback incl. pause/resume TF2 (4.0); geometry shaders (3.2); tessellation shaders (4.0); single-draw indirect glDraw*Indirect (4.0); FBO/MRT/sRGB framebuffers; fence syncs glFenceSync/glClientWaitSync (3.2); sampler objects (3.3); separate shader objects/program pipelines (4.1); packed INT_2_10_10_10_REV normals (3.3); primitive restart; occlusion + timer queries; glMapBufferRange with MAP_INVALIDATE_BUFFER_BIT and MAP_UNSYNCHRONIZED_BIT (3.0).
- macOS GL status (verified Aug 2026): OpenGL 4.1 core still ships and passes conformance on macOS Tahoe (26) on Apple Silicon, implemented as a translation layer on Metal; deprecated since Mojave (2018) with no kill date; AGL (Carbon windowing) was removed from the Tahoe SDK and JUCE saw GL crashes in Tahoe betas — the API works but reliability signals are slowly degrading. macOS 26 is the last Intel release.
- macOS GL quirks that bit or will bite: core-profile-only (VAO mandatory, no compatibility profile); glLineWidth clamped to 1.0 (Ironsight already works around this by drawing point sprites instead of thick lines); no debug callback extension so error hunting is glGetError only; RenderDoc and Xcode GPU capture do NOT work for GL on macOS — frame debugging requires apitrace or a Linux/Windows machine; timer queries exist but are unreliable on the Metal-backed GL, so profile with CPU timers + occasional glFinish.
- ANGLE's Metal backend tops out at OpenGL ES 3.0 (WebGL 2 level) and the ANGLE team has stated no plans for ES 3.1/compute on Metal — ANGLE is NOT a route to GPU compute on macOS, so 'ES-on-ANGLE' would be a capability downgrade from GL 4.1 (which at least has tessellation/geometry/TF).
- Veldrid is abandoned (frozen Feb 2023); community forks exist — NeoVeldrid (Silk.NET-based binding relayer, macOS via bundled MoltenVK, drop-in API) and veldrid2 (bugfix-only). Silk.NET.WebGPU 2.23.0 (Winter 2025) binds wgpu-native 1:1; wgpu-native releases are explicitly 'snapshots' and WGSL/spec details still churn. Both are real but neither adds a capability this game needs, since soil sim and physics are CPU-bound by design.
- Ironsight renderer architecture (read from source): imperative-shell Renderer(gl) class holding raw mutable GL handles; GlUtil module for compile/link, stride-9 pos3/normal3/materialId1/uv2 interleaved VBO layout, matrix upload via fixed pointers; Shaders.fs = inline GLSL 410 strings; all materials procedural in the fragment shader via integer materialId dispatch (brick/wood/concrete/sand/rust each ~5 lines of hash/fbm noise); sky = fullscreen triangle from gl_VertexID with fbm clouds + azimuthal ridge silhouettes + per-level palette uniforms (SkyPalette.fs); one 2048x2048 depth-only shadow FBO, front-face culling during shadow pass, 3x3 PCF with slope-scaled bias, single hardcoded ortho light matrix; HUD = immediate-mode quad batcher with procedurally generated font atlas (FontGen), outline via 3x3 max-tap in shader; Particles = CPU lists of lines + point-sprite puffs, whole-buffer re-upload per frame, additive blend for lines, alpha blend + DepthMask(false) for puffs, capped at 256 lines / 1024 puffs; manual pow(1/2.2) gamma, distance fog, desaturation + contrast grade in the level shader; decals = 16 vec4 uniform array of darkened impact spheres.
- Ironsight main loop (Program.fs): Silk.NET window Update event runs a fixed 1/60 accumulator (clamped to 0.25s) stepping the pure sim; Render event interpolates previous/current world by alpha = accumulator/fixedStep via RenderInterpolation.world and hands the interpolated immutable World to Renderer.Render; cosmetic state (recoil, particles, ragdolls) steps on wall-clock or per-tick StepEffects — presentation is fully derived from sim state plus events, never authoritative.
- Buffer streaming without persistent mapping (the 4.1 pattern): re-specifying via glBufferData with a fresh pointer each frame orphans the old storage and lets the driver pipeline uploads without stalls — this is exactly what Ironsight's GlUtil.upload already does for actors/guns/particles every frame; alternatives for partial updates are glMapBufferRange(INVALIDATE_BUFFER) for whole replacement or (UNSYNCHRONIZED + round-robin ranges + fences) for sub-range streaming. glBufferSubData into a buffer the GPU is still reading stalls; avoid it for hot buffers.
- Per-vertex baked AO from the voxel/SDF volume (sample occlusion in a handful of directions during chunk meshing, store 1 byte per vertex) delivers the 'trench reads deep' effect deterministically at zero per-frame cost — this is the standard voxel-game approach and is strictly better suited to dug holes than SSAO, which needs an extra FBO pass, depth+normal targets, noise rotation, and a blur; SSAO-lite (half-res, 8 samples) remains a feasible 4.1 add-on later since FBO/MRT/depth textures are all available.
- Instanced loose-soil budget: 50k instances x ~32-byte per-instance record = 1.6 MB/frame = ~100 MB/s at 60 Hz — trivial upload bandwidth; a 40-tri clod at 50k instances = 2M tris, comfortably within Apple Silicon GL throughput. The practical limiter is the CPU sim (BEPU handles low thousands of live rigid bodies), so the visual layer should be mostly cosmetic particles ballistically simulated on the CPU against the heightfield/SDF (cheap point-vs-volume queries), not physics bodies. Transform feedback GPU particles are possible in 4.1 but pointless here: particles must query the CPU-side soil volume to settle, so a GPU-resident sim would fight the architecture.
- Triplanar procedural texturing in GLSL 410 is straightforward: weights = pow(abs(normal), 4) normalized, evaluate the procedural material function (hash/fbm, same idiom as Ironsight's materialColor) in the two dominant planes (3-plane only where weights demand), inputs from interpolated per-vertex material/moisture/compaction attributes; wet darkening = albedo * mix(1.0, ~0.55, moisture) plus a specular boost; no image assets required, matching the author's fully procedural style.
- Parallax occlusion mapping for track ruts is expressible in GLSL 410 but is the wrong tool: tracks deform the actual soil volume in this design, so ruts should be geometry from remeshing (plus a normal-perturbation detail noise in the shader); POM would double fragment cost on the largest surface in the scene to fake what the sim already does for real.

## Recommendations

- Stay on Silk.NET OpenGL 4.1 core. Keep every GL call behind Renderer.fs/GlUtil.fs/Shaders.fs as in Ironsight so the (someday) forced move to WebGPU/Metal is a two-file port. Do not adopt Veldrid/NeoVeldrid or Silk.NET.WebGPU now — no needed capability, full idiom rewrite.
- Copy Ironsight's skeleton wholesale: Domain.fs (pure state) / Sim (fixed 60Hz, accumulator + interpolation via RenderInterpolation) / Renderer.fs (imperative shell class) / GlUtil.fs / Shaders.fs (inline GLSL 410 strings) / Hud.fs (quad batcher + FontGen) / Particles.fs (CPU lists, point sprites). Extend rather than redesign.
- Terrain chunks: 32^3 voxel chunks, one VAO/VBO/IBO per chunk (pool and recycle GL objects, don't create/delete per remesh). On remesh, upload with glBufferData(DynamicDraw) whole-buffer orphaning via the existing GlUtil.upload. Budget remeshing: dirty-queue with 4-8 chunk uploads/frame max, nearest-to-bucket first; mesh on background threads, upload on the GL thread only.
- Terrain vertex format (keep stride small for streaming): pos 3xfloat32, normal packed GL_INT_2_10_10_10_REV (4 bytes), material weights 4xu8 normalized (blend up to 4 soil materials), moisture u8, compaction u8, bakedAO u8, pad u8 = 24 bytes/vertex. Normals from SDF central-difference gradient at mesh time — smooth for free, no adjacency pass.
- Bake per-vertex AO from the voxel volume during meshing (8-12 occlusion rays or a 3x3x3 density tap); apply it to the ambient term. Ship this before considering SSAO. Add half-res 8-sample SSAO only if trenches still read flat.
- Fragment shading for terrain: evolve Ironsight's materialColor() into a triplanar procedural soil function — hash/fbm dirt, gravel, clay, sand variants selected/blended by the 4 vertex material weights; wet-darkening from the moisture attribute (darken albedo ~45%, tighten specular); disturbed-vs-undisturbed surface distinction via a per-vertex 'freshly cut' flag driving a rougher, darker, chunkier noise. No texture assets; keep the material atlas path from Ironsight only if you later want authored detail.
- Skip parallax occlusion mapping. Ruts and track marks are real deformation (the sim stamps the volume; remesh does the rest) plus a cheap screen-space normal perturbation noise for micro-detail.
- Loose soil: one instanced draw of a procedurally generated low-poly clod mesh (icosahedron-ish, 20-80 tris, per-instance hash-deformed in the vertex shader by instance id). Per-instance buffer (divisor 1): pos 3xfloat, uniform scale + packed orientation, color/moisture u8x4 — re-uploaded each frame with orphaning. Start with a 20k instance cap; only a few thousand are BEPU bodies, the rest are cosmetic ballistic particles integrated on the CPU against the soil SDF. Note: no baseinstance in 4.1, so if you split draws, rebind attrib offsets or use separate instance buffers.
- Dust and debris: extend Ironsight's Particles.fs point-sprite system (it already handles growth, gravity, additive/alpha passes, depth-mask discipline). Raise the caps (1024 puffs will be too few around a digging bucket; try 8-16k and move from F# list to a preallocated struct array — the list-based aging in Ironsight allocates per frame and will show up at these counts). Fade by age instead of soft-particle depth-fade; revisit soft particles only if intersections with terrain look bad.
- Shadows: reuse Ironsight's single 2048 (bump to 4096) depth-only ortho shadow map, front-face culling, 3x3 PCF, slope-scaled bias — but make the light matrix track a box fitted around the excavator + dig area instead of a hardcoded whole-level ortho. One cascade suffices while the camera orbits one machine; add a second cascade only if the world grows past ~150m of visible range.
- Sky and grade: reuse the fullscreen-triangle sky shader (gl_VertexID trick) with a new SkyPalette: overcast ochre-grey industrial wasteland, low warm sun, heavier haze, dust-tinted distance fog; keep the manual pow(1/2.2) gamma, desaturation and contrast grade from the level shader — that grade is a large part of Ironsight's look and will carry the aesthetic.
- Use one std140 UBO for per-frame camera/sun/fog/grade state shared by terrain, machine, and particle programs (4.1 has UBOs; Ironsight's per-program uniform spam is fine at its scale but the new game has more programs).
- Excavator rendering: procedural meshes exactly like Guns.fs/MeshGen — boxes/cylinders composed per part, one VAO for the machine, per-part model matrices as uniforms (cab, boom, stick, bucket, two tracks ≈ 7 draws; don't bother instancing). Track links can be one instanced draw along the track spline if you want visible link articulation.
- Development workflow: since macOS has no GL frame debugger, keep the renderer runnable on Linux/Windows (Silk.NET is cross-platform) and do RenderDoc sessions there; on macOS profile with CPU timers around glFinish at frame end, not GL timer queries.

## Risks

- Apple could remove OpenGL in a future macOS (post-Tahoe); AGL was already removed from the Tahoe SDK and JUCE reported GL crashes in Tahoe betas. Mitigation: the Renderer.fs isolation boundary; WebGPU via Silk.NET (2.23.0) or NeoVeldrid/MoltenVK are the escape routes.
- glBufferSubData into a buffer still in use by the GPU causes sync stalls — the classic 4.1 perf cliff for streamed terrain. Always orphan (glBufferData full re-spec) or use MapBufferRange(INVALIDATE_BUFFER); never sub-update a hot buffer in place.
- No debug output extension and no RenderDoc/Xcode GPU capture for GL on macOS: a black screen is glGetError archaeology. Budget for cross-platform runs to debug frames elsewhere.
- Ironsight's per-frame Seq.collect/Array.concat CPU flattening (flattenVertices, particle vtx arrays) allocates heavily; fine at FPS scale, but at 50k instances + 10k particles + several chunk remeshes per frame it will trigger GC hitches in a 60Hz fixed-step game — move hot upload paths to preallocated float32[]/struct arrays and Span-based writes.
- Point sprite size is clamped (GL_POINT_SIZE_RANGE, implementation-dependent, historically ~64-511px on Apple); very large near-camera dust puffs can silently clamp — fall back to instanced camera-facing quads for big smoke.
- glLineWidth is clamped to 1.0 on macOS core profile (author already knows); any 'thick line' UI/debug drawing must be quads or points.
- No baseinstance (4.2) and no multi-draw-indirect (4.3): each instanced sub-population (clods vs rocks vs debris) is its own draw with its own instance buffer binding; don't design for a single mega-indirect-draw.
- UBO minimum guarantee is 16KB (std140); don't design a material table that assumes 64KB without querying GL_MAX_UNIFORM_BLOCK_SIZE.
- Transform-feedback particle sim on the Metal-backed GL is a poorly-trodden path (TF is supported but exercised by little modern software); if ever tempted, prototype early — but the architecture (particles must read CPU-side soil state to settle back into the volume) argues for CPU sim regardless.
- SSAO on the Metal-backed GL means full scene into an FBO + extra passes at retina resolution (framebuffer is 2x logical on every Mac) — half-res or skip; retina pixel counts are the silent fill-rate killer on this platform (Ironsight already tracks framebuffer vs logical size in Resize).
- wgpu-native/WGSL churn: if the WebGPU hedge is ever exercised, expect breaking changes between snapshot releases; pin versions hard.
